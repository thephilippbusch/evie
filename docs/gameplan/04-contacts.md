# 04 — Contacts

**Kind:** vertical · **Status:** pending

## Requirements
- Stage 02 — users and profiles must exist.

## Desired outcome
Users keep an explicit list of contacts they can quickly invite to events.

## Scope
### In scope
- Contact requests: send (by email or from a user search), accept, decline, cancel.
- Contact list: view, search, remove.
- Privacy: only accepted contacts see each other's profile details; blocking a user.
- Contact-request notifications as plain in-app indicators (email/push follow when stage 06 lands).

### Out of scope
- Inviting contacts to events (stage 07 uses the contact list).
- Importing address books.
- Groups or lists of contacts (possible later stage).

## Milestones
1. **Contact requests**: done when a user can send a request to an email or an existing user, and the recipient can accept or decline.
2. **Contact list**: done when users can browse, search and remove their contacts.
3. **Privacy & blocking**: done when profile visibility follows contact status and blocked users can't send requests.
4. **Unregistered emails**: done when a request to an unknown email is stored and resolved once that person signs up.
