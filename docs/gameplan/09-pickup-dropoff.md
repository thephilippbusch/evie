# 09 — Pick-up & drop-off

**Kind:** vertical · **Status:** pending

## Requirements
- Stage 07 — attendees, on-behalf participation and event notifications must exist.

## Desired outcome
Attendees can request a ride to or from places like stations, airports or hotels, and organizers, hosts or other attendees can accept it.

## Scope
### In scope
- Ride requests: pick-up or drop-off, place (free text or address), date and time, number of people, notes (luggage, mobility needs).
- On-behalf requests for household members and managed profiles; one request can cover several people.
- Open request board per event, visible to organizers, hosts and attendees.
- Accepting a request: any organizer, host or attendee can take it; the requester sees who accepted.
- Cancelling or releasing a ride by either side.
- Notifications: new request (to drivers), accepted, changed, cancelled, reminder before the ride.

### Out of scope
- Maps, routing or live location.
- Bundling several requests into one trip (possible later stage).
- Payment or cost sharing.

## Milestones
1. **Ride requests**: done when attendees (or someone acting for them) can create, edit and cancel pick-up and drop-off requests.
2. **Request board & acceptance**: done when participants see open requests and can accept or release them.
3. **Overviews**: done when organizers see all rides for the event and attendees see their own rides and the rides they're driving.
4. **Notifications**: done when request, acceptance, change, cancellation and reminder notifications are sent.

## Open questions
- Can one person accept only part of a request (e.g. two of four passengers)?
- Should a request be linked to an accommodation or activity location as its destination automatically?
- Time windows vs. exact times, and what happens to an accepted ride when the time changes?
